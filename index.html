02 컴퓨터와 프로그램

문법 전에 “프로그램이 뭘 하는 물건인지”만 잡으면 뒤 설명이 전부 연결됩니다.

한 줄 비유

컴퓨터는 받은 정보(입력)를 계산·판단(처리)해서 결과(출력)를 보여 주고, 필요하면 기억(저장)하는 기계입니다. 프로그램은 그 일을 시키는 설명서입니다.

부품역할게임으로 치면
CPU명령 계산이동·충돌·점수 계산
RAM지금 쓰는 작업 공간플레이어 좌표, 임시 상태
저장장치오래 보관설치 파일, 세이브
GPU화면 그리기 연산캐릭터·이펙트 렌더
C++와 연결: 변수·배열·객체는 대부분 RAM 이야기고, 코드는 CPU가 실행하는 명령입니다. → 10 · 스택과 힙으로 이어집니다.

03 컴파일과 실행

사람이 쓴 글이 컴퓨터가 읽을 말로 바뀌는 과정입니다.

소스 → 실행 파일

C++ 파일은 사람이 읽기 좋은 텍스트입니다. 컴파일러가 이를 기계어(실행 파일)로 바꿉니다.

1
소스 코드 .cpp — 우리가 편집하는 파일
2
컴파일 — 문법 검사 + 기계어 변환 (에러 나면 여기서 멈춤)
3
실행 — OS가 프로그램을 메모리에 올리고 CPU가 실행
팁: “실행이 안 돼요”의 절반은 컴파일 에러입니다. 빨간 줄·터미널 메시지를 번역기라도 읽으면 성장이 빨라집니다.
보강 예정: OS별 설치·한 줄 컴파일 명령 (Windows / macOS / Linux)

04 첫 프로그램

모든 C++ 프로그램은 대략 main에서 시작합니다.

#include <iostream>   // 입출력 도구 상자

int main() {
    std::cout << "Hello!\n";  // 화면에 출력
    return 0;                 // 정상 종료
}
  • #include = 필요한 도구 가져오기
  • std::cout = 표준 출력(화면)
  • return 0 = “문제 없이 끝났어요”
  • std = 표준 라이브러리 네임스페이스 → 사전에서 검색
  • 이 repo의 src/hello.cpp로 첫 컴파일 확인

05 변수와 타입

변수 = 이름 붙인 상자. 타입 = 상자에 넣을 종류의 라벨. 프로그램은 결국 “값을 담아 두고 → 읽고 → 바꾸는” 일의 반복입니다.

자주 쓰는 타입

타입무엇을 담나대략 크기*예시
bool참/거짓1 bytebool alive = true;
char문자 하나1 bytechar key = 'A';
int정수4 byteint hp = 100;
float실수(단정)4 bytefloat t = 0.016f;
double실수(배정)8 bytedouble dist = 3.14;
std::string문자열가변std::string name = "Kim";

*크기는 환경·컴파일러에 따라 달라질 수 있습니다. “대략 이 정도”로 기억하면 됩니다.

상황 · 코드 · 쓰임

상황: 플레이어 이름·레벨·생존 여부를 한 화면에서 다룬다.

#include <iostream>
#include <string>

int main() {
    std::string name = "Hero";
    int level = 1;
    bool alive = true;

    std::cout << name << " Lv." << level
              << (alive ? " (alive)\n" : " (down)\n");
}

쓰임: UI 상태, 세이브 데이터 필드, 컴포넌트 멤버 변수 — 전부 “타입 있는 상자”입니다.

선언과 대입

int score;      // 선언 (값은 미정일 수 있음)
score = 0;      // 대입
int combo = 3;  // 선언 + 초기화 (권장)
습관: 만들 때 바로 초기값 넣기. “쓰레기 값” 실수를 줄입니다.

signed / unsigned 한 줄

  • int — 음수·양수 (일반 선택)
  • unsigned — 0 이상만 (개수·인덱스 등)
  • 섞어 쓰면 비교·뺄셈이 헷갈릴 수 있음 → 처음엔 int로 통일

06 연산자

값에 대해 계산·비교·논리를 수행하는 기호. 게임 로직의 “수식”이 여기 모입니다.

종류 한눈에

종류기호한 줄
산술+ - * / %더하기·빼기·곱·나누기·나머지
대입= += -= *= /=상자에 넣거나 누적
증감++ --1 늘리기 / 줄이기
비교== != < > <= >=참/거짓 만들기
논리&& || !그리고 / 또는 / 아님

상황 · 코드 · 쓰임

상황: 점수 가산, 쿨다운 감소, “살아 있고 탄약이 남았는지” 판정.

int score = 100;
score += 50;           // 150  (score = score + 50)
++score;               // 151

int ammo = 3;
bool canFire = (ammo > 0) && alive;

// 함정: 정수 나눗셈
int a = 5 / 2;         // 2  (소수 버림)
double b = 5.0 / 2.0;  // 2.5

쓰임: 데미지 공식, 이동 속도, 조건 플래그, 타이머 틱.

자주 하는 실수

  • = (넣기) vs == (같은지)
  • int / int → 소수 버려짐
  • % 는 정수 나머지 (짝/홀, 슬롯 순환)

나머지의 쓰임

// 3칸마다 한 번씩
if (frame % 3 == 0) {
    // 스폰 or 깜빡임
}

주기·그리드·원형 버퍼 인덱스에 자주 등장합니다.

07 조건과 반복

if는 갈림길, for / while은 같은 일을 여러 번. “언제 갈라지고, 몇 번 도는가”가 프로그램의 흐름입니다.

if / else — 갈림길

상황: HP에 따라 메시지·상태를 바꾼다.

int hp = 30;
if (hp <= 0) {
    std::cout << "Game Over\n";
} else if (hp < 30) {
    std::cout << "Danger\n";
} else {
    std::cout << "OK\n";
}

쓰임: 사망 판정, 등급 컷, 버튼 활성/비활성, 충돌 후 반응.

for — 횟수가 정해진 반복

상황: 3틱 카운트, N명의 적 순회 전 단계.

for (int i = 0; i < 3; ++i) {
    std::cout << "tick " << i << "\n";
}
// i = 0, 1, 2  → 세 번

쓰임: 배열/목록 순회, 웨이브 카운트, UI 슬롯 그리기 루프.

while — 조건이 참인 동안

상황: 체력이 남아 있는 동안 턴을 돌린다.

int hp = 100;
while (hp > 0) {
    hp -= 40;
    std::cout << "HP " << hp << "\n";
}
주의: 조건을 깨는 변화(hp -= …)가 없으면 무한 루프. 엔진 틱에서는 보통 “매 프레임 한 번” 구조라 while보다 for/이벤트 분기가 더 흔합니다.

switch — 여러 갈래 중 하나 (맛보기)

int state = 1; // 0=Idle, 1=Run, 2=Jump
switch (state) {
    case 0: std::cout << "Idle\n"; break;
    case 1: std::cout << "Run\n";  break;
    case 2: std::cout << "Jump\n"; break;
    default: std::cout << "?\n";   break;
}

쓰임: 상태 머신, 메뉴 번호, 키 입력 분기. break 빼먹으면 아래 case로 흘러갑니다.

다음: 같은 분기를 여러 곳에서 복붙하게 되면 → 08 · 함수로 묶습니다.

08 함수

일을 묶은 레시피 카드. 이름 한 번으로 같은 처리를 여러 곳에서 호출합니다.

기본 형태

// 반환타입 이름(매개변수...) { 본문 }
int add(int a, int b) {
    return a + b;
}

void shout(const std::string& msg) {
    std::cout << msg << "\n";
    // return 없음 (void)
}
  • 입력(매개변수) → 처리 → 출력(return)
  • void = 돌려줄 값 없음 (출력·상태 변경만)
  • 함수 안 지역 변수는 끝나면 사라짐 → 10 · 스택

상황 · 코드 · 쓰임

상황: 데미지 계산을 스킬·함정·충돌에서 같이 쓰고 싶다.

int applyDamage(int hp, int dmg) {
    hp -= dmg;
    if (hp < 0) hp = 0;
    return hp;
}

int main() {
    int playerHp = 100;
    playerHp = applyDamage(playerHp, 15);  // 85
    playerHp = applyDamage(playerHp, 90);  // 0
    std::cout << playerHp << "\n";
}

쓰임: 전투 공식, 아이템 효과, 저장/로드 헬퍼, 엔진 쪽 “유틸 함수”.

왜 나누나

  • 복붙 줄이기
  • 이름만 보고 의도 파악
  • 한곳만 고치면 전부에 반영

값으로 넘기기 (기본)

인자는 기본적으로 복사되어 들어갑니다. 원본 HP를 바꾸려면 반환값을 다시 대입하거나, 나중에 배우는 참조/포인터(11)를 씁니다.

playerHp = applyDamage(playerHp, 15);

09 배열과 문자열

같은 종류 여러 개 = 배열, 글자 여러 개 = string. “한 줄로 선 상자” 이미지만 잡으면 됩니다.

배열 — 연속 상자

상황: 최근 점수 3개를 순서대로 보관.

int scores[3] = {90, 80, 100};
//  index:  0    1    2

scores[1] = 85;           // 두 번째 칸 수정
int sum = scores[0] + scores[1] + scores[2];

for (int i = 0; i < 3; ++i) {
    std::cout << scores[i] << "\n";
}

쓰임: 고정 길이 버퍼, 키보드 키 맵, 작은 룩업 테이블. 인덱스는 0부터.

범위: scores[3] 은 없는 칸(0..2만 유효). 넘어가면 미정의 동작.

std::string — 문자열

상황: 캐릭터 이름, UI 문구, 파일 경로.

#include <string>
#include <iostream>

std::string name = "Hero";
name += " II";              // "Hero II"
std::cout << name.size();  // 글자 수(바이트/구현 주의는 나중)
std::cout << name[0];      // 'H'

쓰임: 로그 메시지, 세이브 키, 리소스 경로. C 스타일 char[]보다 일상 코드에선 string이 편합니다.

배열 vs 곧 배울 vector

배열 T a[N]vector (13)
길이컴파일 때 고정인 경우가 많음실행 중 push_back으로 늘어남
편함단순·가볍목록·스폰·인벤토리에 강함
지금“연속 상자 + 인덱스” 감각실무 목록은 여기로
권장 루트: 09에서 인덱스·string만 익히고, 늘어나는 목록은 13 · STL · vector로.

10 스택과 힙

둘 다 RAM 안의 작업 공간입니다. 차이는 문법 이름보다 누가 관리하고, 얼마나 오래 사느냐에 가깝습니다.

한눈에 비교

스택 (Stack)힙 (Heap)
관리자동 (함수 끝나면 정리)프로그래머 / 스마트 포인터
속도매우 빠름상대적으로 느림
용도지역 변수, 함수 인자크기·수명이 자유로운 데이터
비유계산용 메모지 (끝나면 버림)창고 대여 (반납 규칙 필요)
수명블록/함수와 함께직접 끊을 때까지 (또는 스마트 포인터)

메모리 도식 (개념 + 애니메이션)

물리적으로는 더 복잡하지만, 학습용으로 RAM을 구역으로 나눠 보면 됩니다. 스택은 위에서 아래로, 힙은 아래에서 위로 차곡차곡 늘어납니다.

함수 호출 → 스택 블록 · 동적 할당 → 힙 블록

스택 (자동) 빈 공간 힙 (동적) 전역/정적 코드
기억: 스택은 “함수 끝나면 자동 청소”, 힙은 “빌려 쓴 뒤 반납 규칙이 필요”. 반납을 현대적으로 다루는 법은 15 · 스마트 포인터.

상황 · 코드 · 쓰임 — 스택

상황: 함수 안에서만 쓰는 임시 계산, 작은 상태.

void tick() {
    int damage = 10;     // 스택 (지역)
    int shield = 3;      // 스택
    int net = damage - shield;
    // tick이 끝나면 damage, shield, net 전부 사라짐
}

쓰임: 매 프레임 임시 값, 루프 카운터, 작은 구조체 값 — 기본은 스택이 안전하고 빠름.

상황 · 코드 · 쓰임 — 힙이 필요한 때

상황: “함수가 끝나도” 살아 있어야 하거나, 크기를 실행 중에 정해야 할 때.

// 개념만 (raw new는 나중에 스마트 포인터로 대체)
int* big = new int[1000];  // 힙에 1000칸
// ... 여러 함수에서 big을 넘기며 사용 ...
delete[] big;              // 반납 (안 하면 누수)

쓰임: 긴 수명의 리소스, 큰 버퍼, 엔진 객체가 “월드에 남아 있는” 느낌. 일상 목록은 보통 vector(13)가 힙을 대신 관리해 줍니다.

지금 목표: raw new 숙달이 아니라 “스택 = 자동 / 힙 = 수명 설계” 감각. 상세 할당은 14, 안전한 소유는 15.

선택 가이드

  • 작다 + 함수 안에서만 → 스택 (일반 변수)
  • 목록이 늘어난다 → vector (13)
  • 소유·수명이 복잡 → 스마트 포인터 (15)
  • 초보 구간에서 raw new 남발

힙·객체를 가리키려면 주소가 필요합니다. 그 주소 이야기가 바로 11 · 포인터와 참조입니다.

11 포인터와 참조

값 vs 그 값이 있는 곳(주소). 목표는 100% 숙달이 아니라, 머리속에 화살표 그림이 그려지는 것입니다.

한 줄 정의

  • 포인터 — 주소를 담는 변수. 화살표를 들고 다님.
  • 참조 — 이미 있는 변수에 붙인 별명. 문법상 값처럼 씀.
  • 둘 다 “복사본이 아니라 원본을 건드리고 싶을 때” 등장

포인터 — 주소와 역참조

상황: 변수 x가 있는 위치를 다른 이름으로 찾아가 수정.

int x = 10;
int* p = &x;   // &x = x의 주소, p가 그 화살표를 보관
*p = 20;       // * = 따라가서 값 쓰기 → x도 20

// 그림:
//   p  ──────►  x [ 20 ]
기호읽는 법
int* pp는 “int가 있는 곳”을 가리킴
&xx의 주소 (화살표 만들기)
*pp가 가리키는 그 값 (따라가기)
nullptr아무 데도 안 가리킴 (빈 화살표)

쓰임: 배열 Decay, C API, 엔진에서 “이 액터 포인터”, 선택적 대상(있을 수도/없을 수도).

참조 — 별명

상황: 함수에 넘길 때 복사 없이 원본 HP를 바꾸고 싶다.

void hurt(int& hp, int dmg) {
    hp -= dmg;          // 원본이 바뀜
    if (hp < 0) hp = 0;
}

int main() {
    int playerHp = 100;
    hurt(playerHp, 30); // playerHp == 70
}

참조는 선언 시 반드시 누군가를 가리켜야 하고, 보통 다시 “다른 대상”으로 갈아끼우지 않습니다.

쓰임: 함수 인자(T&, const T&), 큰 객체 읽기, 범위 for (for (auto& e : list)).

포인터 vs 참조 (실무 감각)

포인터 T*참조 T&
빈 상태nullptr 가능보통 “항상 유효한 별명”
재지정다른 주소를 다시 담을 수 있음처음 묶인 대상이 기본
문법*, ->일반 변수처럼 .
선택“없을 수 있음” / C 스타일 API함수 인자로 원본 공유 (아주 흔함)

const 참조 (읽기 전용 별명)

void printName(const std::string& s) {
    std::cout << s;  // 수정 안 함, 복사 비용↓
}

큰 string·구조체를 함수에 넘길 때 기본 패턴에 가깝습니다.

위험 신호 (이름만)

  • 댕글링 — 사라진 대상을 가리킴
  • 널 역참조 — nullptr에 *
  • 현대 코드는 소유를 unique_ptr 등으로 (15)
다음에 이어짐: 데이터+행동을 묶으면 12 · 구조체와 클래스, 같은 종류 여러 개는 13 · vector (내부적으로 힙+연속 저장).

12 구조체와 클래스

데이터 + 행동을 한 덩어리로 묶습니다.

struct Player {
    std::string name;
    int hp;

    void takeDamage(int dmg) {
        hp -= dmg;
        if (hp < 0) hp = 0;
    }
};

int main() {
    Player p{"Hero", 100};
    p.takeDamage(30);
}
  • 멤버 변수 = 상태, 멤버 함수 = 행동
  • struct / class — 기본 접근 권한 차이 (나중에 정리)
  • 게임 캐릭터·아이템이 거의 이 패턴
보강 예정: 생성자, public/private, 상속 맛보기

13 STL · vector

이미 있는 좋은 도구. 가장 먼저 vector.

#include <vector>
#include <iostream>

int main() {
    std::vector<int> scores = {90, 80, 100};
    scores.push_back(70);
    for (int s : scores) {
        std::cout << s << "\n";
    }
}
도구언제
vector가변 길이 목록 (최우선)
string문자열
map / unordered_map키 → 값 사전
algorithm정렬·탐색 등

14 new 와 delete

힙을 빌리고 반납하는 감각. 남용은 금물.

int* p = new int(42);
std::cout << *p << "\n";
delete p;
p = nullptr;  // 습관
현대 습관: raw new 대신 vector(13) / 스마트 포인터(15). 여기서는 “힙과 스택이 다르다”만 확실히.

15 스마트 포인터

메모리를 객체 수명에 묶어 자동 정리 (RAII).

  • unique_ptr — 소유자 하나 (기본 선택)
  • shared_ptr — 공유 소유 (남용 주의)
  • weak_ptr — 순환 참조 끊기
#include <memory>
auto p = std::make_unique<int>(42);
// 스코프 끝에서 자동 해제
보강 예정: 규칙 오브 파이브, 순환 참조 그림

16 이동(move)

큰 데이터를 복사하는 대신 소유권을 이전합니다.

  • 복사 = 내용 복제 (비용 큼)
  • 이동 = 소유권 이전 (std::move)
  • vector가 커질 때 내부적으로 이런 최적화를 많이 씀

17 템플릿

타입을 파라미터로. 같은 로직을 복붙하지 않고 일반화. STL의 기반.

template <typename T>
T max2(T a, T b) {
    return (a > b) ? a : b;
}
// max2(1, 2); max2(1.5, 0.2);
보강 예정: 함수 템플릿 vs 클래스 템플릿, 컴파일 타임 타입

20 활용 예시 · FAQ

숙제·퀴즈 대신 짧은 완성 예시를 보여 주고, “이런 상황에 이렇게 붙인다”만 남깁니다. 따라 쳐도 되고, 눈으로만 읽어도 됩니다.

이 가이드의 읽기 방식

  • 상황 — 언제 쓰는지 한 줄
  • 코드 — 최소 예시 (복붙해도 되는 크기)
  • 쓰임 — 게임/앱에서 어디에 해당하는지
  • 퀴즈, 미션 제출, “직접 구현해 보세요” 강요 없음
현대인 모드: 출퇴근·틈새 시간에 번호 하나 = 카드 하나. 손이 바쁘면 읽기만, 여유가 있으면 예시를 살짝 바꿔 보며 “아 여기가 바뀌는구나” 정도면 충분합니다.

예시 A · 조건 + 반복 (07) — 체력 체크 루프

상황: 매 프레임/매 턴마다 HP를 보고, 0 이하면 게임 오버.

int hp = 100;
while (hp > 0) {
    // ... 데미지 받는 로직이 있다고 가정
    hp -= 30;
    if (hp <= 0) {
        std::cout << "Game Over\n";
    } else {
        std::cout << "HP " << hp << "\n";
    }
}

쓰임: 턴제 전투, 웨이브 종료 조건, UI의 “살아 있음” 표시 분기.

예시 B · 함수 (08) — 데미지 계산 한곳에

상황: 같은 계산을 여러 몬스터·스킬에 복붙하지 않기.

int applyDamage(int hp, int dmg) {
    hp -= dmg;
    if (hp < 0) hp = 0;
    return hp;
}
// playerHp = applyDamage(playerHp, 15);

쓰임: 스킬·버프·충돌 데미지를 이름 있는 한 덩어리로 모아 엔진/게임 코드에서 호출.

예시 C · 클래스 + vector (12–13) — 적 목록

상황: 적 여러 마리의 HP를 한 리스트로 관리.

struct Enemy {
    std::string name;
    int hp;
};

std::vector<Enemy> enemies = {
    {"Slime", 30},
    {"Goblin", 50}
};
enemies.push_back({"Orc", 80});  // 스폰

for (const Enemy& e : enemies) {
    std::cout << e.name << " HP=" << e.hp << "\n";
}

쓰임: 스폰된 액터 목록, 인벤토리 슬롯, 퀘스트 목록 — “같은 모양의 것 여러 개”.

예시 D · unique_ptr (15) — 소유권 한 곳에

상황: 큰 리소스(텍스처·세션)를 누가 지우는지 명확히.

#include <memory>

struct Session {
    int id;
};

void run() {
    auto session = std::make_unique<Session>(Session{1});
    // session이 스코프를 벗어나면 자동 해제
}

쓰임: “이 객체의 주인은 나 하나”일 때. 엔진/툴 코드에서 raw new 대신 자주 보는 패턴.
